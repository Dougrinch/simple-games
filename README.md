# Балда

Мобильная веб-игра для двух заранее разрешённых пользователей:
`grinch131@gmail.com` и `hinhillaa@gmail.com`. Игроки входят через Google,
по очереди добавляют по одной букве и проводят одним движением через клетки
получившегося слова.

Подтверждённое состояние хранится в Firebase Realtime Database, синхронизируется
между устройствами и восстанавливается после перезагрузки. Локальная копия
используется только для просмотра при временном отсутствии сети.

Production URL: <https://dougrinch.com/simple-games/>.

## Локальный запуск

Требуются Node.js 24, npm 11+ и Java 21.

```bash
nvm use
npm ci
cp .env.emulator.example .env.local
```

Запустите три процесса:

```bash
# Терминал 1
npm run emulators

# Терминал 2
npm run emulators:seed

# Терминал 3
npm run dev
```

Для локальной проверки push дополнительно скопируйте
`push-worker/.dev.vars.example` в `push-worker/.dev.vars`, заполните
`VAPID_PRIVATE_KEY` и запустите:

```bash
npm run push:dev
```

- приложение: <http://localhost:5173>
- Emulator UI: <http://localhost:4000>
- Auth Emulator: `127.0.0.1:9099`
- Realtime Database Emulator: `127.0.0.1:9000`

При входе Auth Emulator покажет тестовый экран Google. Используйте один из двух
разрешённых email. Для проверки синхронизации откройте приложение в двух
отдельных профилях браузера и войдите разными игроками.

## Как играть

1. Дождитесь надписи «Мой ход».
2. Нажмите на свободную клетку, которая касается заполненной клетки по стороне.
3. Выберите одну из 33 русских букв на встроенной клавиатуре.
4. Не отрывая палец, проведите через все клетки слова и отпустите на последней.
5. Допустимый ход отправляется сразу. Слово должно включать новую букву, не
   повторять клетки и ранее принятые слова.

Нажатие на другую доступную пустую клетку заменяет текущую черновую букву и
сразу открывает новый выбор. Если закрыть выбор, не указав букву, черновик не
создаётся. Повторное короткое нажатие на черновую клетку удаляет букву, а свайп,
начатый из неё, вводит путь слова. Автор последнего хода может нажать
«Ой, шучушучу», а соперник — «Ненене, так нельзя». Обе кнопки полностью
откатывают только последний принятый ход.

## Проверки

```bash
npm run lint
npm run typecheck
npm run seed:validate
npm run release-notes:check
npm run test:unit
npm run test:firebase
npm run test:worker
npm run push:check
npm run test:unit:coverage
npm run build
npm run check
```

`npm run test:unit` запускает unit- и component-тесты приложения без чтения
локальной production-конфигурации. `npm run test:firebase` поднимает отдельный
Realtime Database Emulator и проверяет границу доступа, конкурентное создание
партии, атомарный ход, конфликт ревизий, откат и финальный результат.
`npm run test:worker` запускает Worker в локальном Workerd с отдельной тестовой
конфигурацией.

## Архитектура

```text
src/app/                         экраны приложения и оркестрация состояний
src/features/auth/               Google Sign-In и список игроков
src/games/balda/domain.ts        чистая игровая логика
src/games/balda/repository.ts    подписки, транзакции и синхронизация
src/games/balda/components/      поле, клавиатура и игровой экран
src/platform/firebase/           инициализация Firebase
src/platform/push/               подписка браузера и вызов Push Worker
src/platform/update/             проверка и применение новых сборок
src/platform/serviceWorker/      общая регистрация service worker
src/features/push/               пользовательский контрол уведомлений
src/features/update/             попап с изменениями после обновления
src/platform/games/              реестр типов игр
push-worker/                     Cloudflare Worker и Workerd-тесты
public/sw.js                     приём и открытие Web Push
tests/rules/                     Emulator-тесты доступа и транзакций
firebase-data/seed.json          schemaVersion и 1554 стартовых слова
```

UI не обращается к Firebase напрямую. Создание выполняется транзакцией над
`/gameTypes/balda`, а ход и откат — транзакцией над текущей партией. Каждая
операция проверяет актуальную ревизию и повторно валидирует состояние.

Онлайн-состояние определяется через `/.info/connected`. При разрыве связи
действия блокируются. После reconnect приложение сначала перечитывает указатель
и партию с сервера, после чего снова разрешает ввод.

## Модель доступа и доверия

Текущие Security Rules намеренно упрощены:

- точные email `grinch131@gmail.com` и `hinhillaa@gmail.com` могут читать,
  создавать, изменять и удалять любые данные Realtime Database;
- неавторизованные пользователи и любые другие email не могут ничего читать
  или записывать.

Следовательно, правила защищают базу только от посторонних. Они не защищают
словарь, завершённые партии или игровую геометрию от одного из двух разрешённых
игроков. Оба игрока считаются доверенными и используют опубликованный клиент.

## Firebase и публикация

Production-переменные, включая `VITE_PUSH_WORKER_URL`, находятся в `.env.local`
и GitHub Actions Repository Variables. `.env.local` исключён из Git. Пошаговая
настройка сторонних сервисов описана в
[docs/external-services.md](docs/external-services.md).

Отдельная инструкция по бесплатным системным push-уведомлениям через Cloudflare
Workers находится в
[docs/push-notifications.md](docs/push-notifications.md).

После изменения `database.rules.json` владелец вручную публикует правила:

```bash
npx firebase deploy --only database --project <FIREBASE_PROJECT_ID>
```

Повторно импортировать `firebase-data/seed.json` поверх рабочей production-базы
нельзя. Push в `main` запускает `.github/workflows/deploy-pages.yml`, который
проверяет проект, собирает Vite с `VITE_BASE_PATH=/simple-games/` и публикует
`dist` через GitHub Pages.

## Release notes и обновление клиента

Перед каждым новым non-merge коммитом нужно добавить ровно одну запись в конец
`release-notes.json`. Номер `id` увеличивается на один, а `text` должен быть
одной короткой строкой не длиннее 80 символов. Для служебного изменения
используется точный текст `Нутрянка`. Старые записи изменять или удалять нельзя.

```json
{
  "id": 2,
  "text": "Исправлено игровое поле"
}
```

`npm run release-notes:check` проверяет формат файла и каждый коммит после его
создания. Эта же проверка обязательна в pull request и перед production-деплоем.

Production-сборка публикует маленький `version.json` и отдельный
`release-notes.json`. Открытый клиент проверяет только версию раз в минуту, при
возвращении на вкладку и после восстановления сети. Новая сборка полностью
перезагружает страницу, проверяет фактическое изменение `sw.js` и показывает
все ещё не подтверждённые заметки в попапе «Приложение обновлено».

## Ручная приёмка

На двух устройствах или в двух браузерных профилях:

1. Войти обоими разрешёнными аккаунтами.
2. Почти одновременно создать игру и убедиться, что появилась одна партия.
3. Проверить стартовое слово, первый ход и синхронизацию счёта, очереди и поля.
4. Отменить собственный ход, повторить его и оспорить вторым игроком.
5. Проверить повторное слово, неправильный путь и выход за поле.
6. Отключить сеть, перезагрузить страницу, восстановить сеть и сверить состояние.
7. Заполнить поле, проверить результат и создать следующую игру.
8. Убедиться, что третий Google-аккаунт не получает доступ.
9. Перезагрузить опубликованный GitHub Pages URL напрямую.
